# app-skeleton — 前後端骨架、身分進場與活動階段同步（v1.1）

檔位：**S**（活動階段狀態機與同步；`contracts/` 首建；跨元件架構）｜主人：@yue083139｜parity：`docs/parity.md` §4 `app-skeleton`｜需求：R-01、R-11｜依賴：無

## 首屏決策摘要

1. **伺服器是唯一狀態來源，WebSocket 推「按身分裁切後的整份畫面狀態」，且只在該連線自己的 view 內容改變時才推**：選了每次狀態變更對每個連線重算 view、與上次送出的比對、相同就不送，訊息序號為每連線各自遞增／代價：每次變更 O(連線數) 次序列化（本機 ≤ 20 連線可忽略）／可被「老師切階段後所有連線收到新階段」與「他組送出時本組收到 0 則訊息」兩個整合測試證偽。
2. **階段狀態機預留「判定中」**：選了 `準備→搶答中→已結束→準備`，`判定中` 已列入列舉與轉移表但經典模式不經過（`docs/trd-game-modes.md` T-03）／代價：多一個目前用不到的狀態／可被轉移表單元測試證偽。
3. **老師身分以啟動時產生的老師金鑰驗證**：選了每次啟動產生隨機金鑰並印在終端機，老師端 API 與 WebSocket 都要帶／代價：老師每次重啟要重新複製網址／屬取捨，理由：本機模擬，不做帳號系統，但學生不能直接打開老師頁偷看全部作答（R-09）。
4. **學生以「組別憑證」綁定組別**：選了學生選組時伺服器發一個隨機憑證，每組同時只發給一台裝置，WebSocket 與送出都必須帶；老師可「釋放」某組讓新裝置加入／代價：同組只能一台裝置作答、裝置掛掉需老師釋放／可被「改網址組別參數但沒有該組憑證 ⇒ 只拿到最少資訊、送出 403」測試證偽。v1.0 曾寫「不驗證、冒用不擴大洩漏面」，評審實證冒用可在搶答中讀到他組答案，已撤回。

**矩陣落點**：M-001（身分進場）、M-002（階段同步）守門改為本卡測試，狀態 covered。

**merge 三問第三問**：需求證實——R-01 兩種使用者、R-11 同步活動階段為核心功能必做。

## 目標

- `server/`：FastAPI 應用、活動狀態（組別、階段、組別憑證）、階段轉移 API、WebSocket 推播、老師金鑰、`python -m quiz_server` 啟動。
- `web/`：首頁選身分（老師輸入金鑰／學生選組別並取得組別憑證）、老師頁（設定組數、開始／結束／重置、各組加入狀態與釋放）、學生頁（顯示目前階段）。
- `contracts/api.md`：REST 端點、WebSocket 訊息外框、階段列舉。
- `make dev`、server／web 測試與 lint 接進 `make gate-pr`；CI 安裝 server 與 web 依賴。

## 邊界（本卡不做）

匯入題目（`guided-notes-import`）、作答與判定（`buzz-answering`）、作答狀況與結果畫面（`results-view`）、匯出（`guided-notes-export`）、任何遊戲模式。
